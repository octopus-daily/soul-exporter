# Soul App 内容导出方案（网页版 / PC 端）

> 调研时间：2026-10-15
> 结论一句话：**Soul 的「PC 端」就是 `https://home.soulapp.cn` 这个网页版，没有本地数据库可扒；
> 但它的后端接口干净（同源、纯 cookie 鉴权、无签名），所以可以在浏览器里直接批量取自己的内容。**

---

## 一、PC 端到底是什么

| 说法 | 实际情况 | 依据 |
|---|---|---|
| 官方「Soul PC 端」 | 就是网页版 `home.soulapp.cn` | 官网公告原文结尾：「访问 https://home.soulapp.cn ，就能体验」 |
| 官网有安装包吗 | **没有** | `www.soulapp.cn` 首页 HTML 里没有任何 `.exe / .dmg / .msi` 链接，只有扫码下 App 的二维码 |
| 微软商店那个 Soul | 官方上架的 Windows 应用，大概率是同一套网页套的壳 | Microsoft Store 条目存在；未逐字节核实其打包形式 |
| 前端形态 | Vite 打包的 Vue 3 SPA | `/assets/index-Damj4Bc9.js`，Vue 3.5.40 |
| 有无本地缓存库 | 无。数据全在服务端，取数据 = 调 HTTP 接口 | 前端代码里数据全靠 `fetch` |

**所以「自己把东西扒下来」的正确姿势不是找本地文件，而是复刻它的接口调用。**

## 三、鉴权与必须的请求头

### 鉴权：纯 cookie

前端请求封装（位于 `imSession-*.js`）：

```js
{ method, headers, credentials: 'include' }
```

- **没有 `Authorization` / `Bearer`，没有任何签名参数**（`signature` 只是用户签名档字段，不是签名算法）。
- 因此只要浏览器在 `home.soulapp.cn` 上处于登录态，控制台里直接 `fetch` 就能通。

### 必须带的固定请求头（缺了会被拒）

```js
{
  os: 'PC',
  'app-id': '10000010',
  'app-version': '1.0.0',
  version: '1.0.0',
  'channel-id': 'official',
  'device-id': localStorage.getItem('soul_device_id') || <UUID>,
  'Content-Type': 'application/json',
}
```

### 返回码约定（重要）

- **成功 = `code === 10001`**（从打包代码 `if (n.code !== 10001) throw ...` 反推）。
- `20001` = 权限验证失败 / 登录失效（未登录时所有接口都是这个）。
- `10002` = 服务端临时异常。

### 实测验证（无凭据访问）

```
/pc/config                -> {"code":20001,"message":"权限验证失败，请重新再试"}
/pc/profile/info          -> {"code":20001,...}
/pc/profile/content/posts -> {"code":20001,...}
/pc/v3/post/detail        -> {"code":10002,...}
```

即：**接口真实存在且可达，只差登录 cookie**，无签名门槛。

## 四、瞬间列表的分页规则（照搬前端原逻辑）

请求参数：

| 参数 | 说明 |
|---|---|
| `targetUserIdEcpt` | 目标用户 ID（自己的从 `localStorage.soul_userIdEcpt` 取） |
| `pageSize` | 前端固定 **15** |
| `orderType` | `DESC`（从新到旧） |
| `firstVisitFlag` | 首页传 `'1'`，之后传 `'0'` |
| `lastIdEcpt` | 游标 = **上一页最后一条的 `postIdEcpt`** |
| `includeLastId` | 非首页时传 `'0'` |
| `firstStartTime` | 上一页响应里的 `lastStartTime` 或 `earliestPostTime` |

响应字段：

| 字段 | 说明 |
|---|---|
| `postList[]` | 本页数据，每条含 `postIdEcpt` |
| `count` | 总条数 |
| `lastStartTime` / `earliestPostTime` | 供下一页带 `firstStartTime` |

终止条件：本页为空 / 拿不到游标 / 累计条数 ≥ `count`。

## 五、怎么用

### 第 1 步：导出 JSON

1. 浏览器登录 `https://home.soulapp.cn/`，进「我的」页面；
2. 按 F12 → Console；
3. 把 `_soul_api_export.js` 全文粘进去，回车；
4. 跑完自动下载 `soul_export.json`，内含：
   - `profile` / `metrics`（资料与计数）
   - `tabs`（内容分类）
   - `posts`（全部瞬间，原始字段）
   - `videoPosts`（视频标签页）
   - `mediaManifest`（按条归类的图片 / 视频直链）
   - `mediaUrls`（扁平化直链清单）

脚本里的开关（文件顶部 `CONFIG`）：

| 开关 | 默认 | 作用 |
|---|---|---|
| `WITH_DETAIL` | `false` | 逐条再拉一次 `/pc/v3/post/detail`，字段更全，但 485 条约多花 6~7 分钟 |
| `WITH_VIDEO` | `true` | 额外导出「视频」标签页 |
| `SLEEP_MS` | `800` | 每页间隔，别调太小以免被限频 |

### 第 2 步：批量下载图片 / 视频

```powershell
D:\...\python.exe soul_media_download.py --json soul_export.json --out soul-media
```

- 目录结构：`soul-media\<瞬间|视频>\<序号>_<postIdEcpt>\<序号>_<字段名>.<ext>`
- 断点续传：已下好的文件自动跳过，中断了直接重跑
- `--dry-run` 只看要下什么；`--workers 4` 调并发
- **m3u8（HLS 视频流）本脚本不处理**，遇到会提示，需要 ffmpeg 另行下载

## 八、风险与注意

1. **只导自己的数据**。换 `targetUserIdEcpt` 去批量拉别人内容，既可能被风控，也涉及他人隐私。
2. **别跑太猛**。脚本默认每页间隔 800ms。调成 50ms 有被限频甚至封号的现实风险。
3. **cookie 不落地**。脚本不读取也不上传 cookie，靠浏览器自身的 `credentials: include`。
   但**导出的 JSON 里可能含你自己的隐私信息**（如位置信息），别随手发出去。
4. **接口是内部接口，随版本变**。前端 bundle 文件名带哈希，Soul 一发版就可能全变；
   失效时重新拉 `https://home.soulapp.cn/` 的 HTML，找新的 `/assets/index-*.js`，再按本文方法提取新路径。
5. **易盾验证码**（`/yidun-captcha.js`）只用于登录环节，本方案不涉及登录，故无影响。

## 附：接口是怎么找出来的（可复现的调研步骤）

这套方法**不依赖任何现成工具**，四步就能复现：

| 步骤 | 做什么 | 命令 / 要点 |
|---|---|---|
| 1 | 抓网页版入口 HTML | `GET https://home.soulapp.cn/`，找 `/assets/index-*.js` |
| 2 | 下载入口 bundle 与懒加载分片 | 按 HTML 里的 `<script>` / `import()` 路径逐个下载 |
| 3 | 从分片里 grep 出接口路径 | `grep -oE '"/pc/[a-zA-Z0-9/_\-]+"' *.js \| sort -u` |
| 4 | 无凭据探测接口是否活着 | 不带 cookie 请求：返回 `20001 权限验证失败` = **接口存在、只差登录**；404 = 路径不对 |

**要点**：第 3 步拿到的是**前端代码里真实使用的路径**，比猜路径可靠得多；
第 4 步是关键判据 —— **它把"接口存在"和"接口能调通"两件事分开了**，能省掉大量试错。
